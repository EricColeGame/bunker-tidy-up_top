## 每个货架位置需要追踪什么

Bunker Tidy Up 中最常见的失误并不是漏掉某个货架——而是忘记自己已经处理过哪些货架。记忆撑不过房间之间的那段路，两条相似的走廊也很容易混为一谈。

为每个储藏区域记录三件事：它在哪里、存放哪一类物品、以及是否已彻底检查过。看起来空无一物的货架，可能仍属于某个更大的储藏区；而一个只整理了一半的货架，也会让已经完成的房间看起来尚未完工。

| 字段 | 记录内容 | 有何帮助 |
| --- | --- | --- |
| 区域名称 | 房间、走廊、角落或储藏区 | 防止重复搜索 |
| 货架标识 | 左、中、右、上或下 | 区分彼此仅相隔几英寸的货架 |
| 物品分组 | 电池或其他可见类别 | 保持跨房间的分类一致 |
| 状态 | 未检查、进行中、已整理、已核验、待定 | 一眼看出下一个任务 |
| 备注 | 缺失物品、视线受阻或需要复查的原因 | 为之后的游玩保留线索 |

使用固定的命名模式，例如 **Room A - Shelf 01** 或 **Storage West - Upper Rack**。具体的用词并不重要，重要的是保持一致。当多个区域共用相同布局时，稳定的标签是唯一可靠的区分方式。

### 房间清扫、货架巡检、核验复查

- **房间清扫：** 进入房间，沿着一面墙走，把这条线上可见的货架全部处理完，再改变方向。
- **货架巡检：** 从上到下检查每一个货架，然后立刻记录。
- **核验复查：** 只重新查看被标记的货架，而不是把整个地堡重来一遍。

社区反馈一致表明，核验复查正是玩家最容易跳过的一步——也是造成大多数重复计数的一步。

## 路线规划：如何覆盖每个位置而不走回头路

路线能修正最常见的货架定位错误：同一个角落检查了三遍，而整片区域却从未被触碰。下面这套顺序不依赖具体的房间布局，因此随着你对地图的熟悉程度提升，它依然适用。

1. **选一个地标。** 使用主入口、宽大的门洞，或某件特征鲜明的设备。这个地标就是路线重置的位置。
2. **先清空一侧。** 沿着左墙或右墙前进，在穿过房间之前检查每一个可见货架。来回穿越会造成遗漏。
3. **保持同一检查方向。** 每个货架都从上到下或从下到上查看，绝不在中途切换。检查完货架后立刻记录。
4. **标记任何不确定的地方。** 如果有物体或角度妨碍你做出确定的检查，就把该货架标为待定。标为待定永远比草率地判定为空更安全。
5. **闭合回路。** 回到起始地标，在继续前进前把房间与你记录的内容对照一遍。

| 路线阶段 | 你要做的事 | 完成信号 |
| --- | --- | --- |
| 起点 | 选择地标并给区域贴上标签 | 起始点已记录 |
| 第一遍 | 沿着一面墙或一条通道前进 | 每个可见货架都有状态 |
| 细节检查 | 检查上层、中层与下层分段 | 没有任何货架分段被跳过 |
| 例外处理 | 重新查看受阻或不确定的货架 | 待定条目已解决 |
| 离开检查 | 把房间与记录对照 | 路线回到地标 |

当房间里多个货架靠得很近时，把它拆成更小的分区。像 **北墙**、**中央货架** 和 **门边货架** 这样的标签，定位缺失物品的速度远快于一个笼统的"储藏室"标签。

### 避免误判完成

不要因为前排看起来整齐就把货架标记为完成。隐藏的、高处的或被遮挡的部分应保持待定，直到你能有把握地检查它们。关于 Bunker Tidy Up 的社区反馈反复提到这一点：一排整齐的前排物品背后，可能隐藏着整整一层尚未处理的内容。

## 电池与货架分组的整理优先级

最好的整理系统，是你能不假思索地重复执行的系统。先从看得见、容易归位的物品开始，然后利用空出来的货架空间去暴露仍然缺失的东西。在房间之间随意搬动物品，只会让你的记录变得无法阅读。

针对电池目标，三阶段优先级效果很好：

1. 收集当前区域内所有可见的电池。
2. 把它放入正确的货架分组，或一个标记清晰的工作暂存堆。
3. 放置后核验该货架，避免同一区域被重复计数。

| 优先级 | 任务 | 建议操作 |
| --- | --- | --- |
| 高 | 当前区域内的可见电池 | 立即收集并记录 |
| 高 | 状态不确定的货架 | 标为待定，离开前检查 |
| 中 | 部分整理过的货架 | 先把该区段完成再扩展 |
| 中 | 附近的散落物品 | 按可见类型或货架用途分组 |
| 低 | 此前已核验的货架 | 仅在数量对不上时再查看 |

关于 Bunker Tidy Up 的参考资料与社区内容提到，游戏中需要寻找并整理 420 块电池，这正是基于区域的里程碑胜过单一总数目标的原因。按房间计数，而不是按整个地堡计数。

| 代码 | 含义 | 下一步操作 |
| --- | --- | --- |
| U | 未检查 | 在下一轮路线中检查 |
| A | 进行中 | 当前正在搜索或整理 |
| S | 已整理 | 物品已放置，区域视觉上已归整 |
| V | 已核验 | 整理后已复查 |
| P | 待定 | 因通道或视线受阻需要复查 |

在记录中，**已整理** 与 **已核验** 之间的差别比其他任何区分都更重要。已整理意味着在你本轮处理之后，货架看起来井然有序。已核验意味着你回来确认过没有任何可见的东西被遗漏。只有完成房间的完整路线之后，才把货架提升为已核验。

## 货架位置清单与进度复查

每次开始游戏时都执行这份清单。它只需不到一分钟，却能防止那种把干净地堡慢慢变成一团混乱的漂移。

- 选择一个地标并为当前区域命名
- 沿一致的方向检查货架
- 给每个货架一个状态：未检查、进行中、已整理、已核验或待定
- 把已完成的房间与仍在进行中的房间分开
- 在开始新一轮大范围清扫前清空待定货架

| 复查问题 | 通过条件 | 若不通过 |
| --- | --- | --- |
| 每个可见货架都有标签了吗？ | 没有未命名的货架 | 离开前补上标签 |
| 路线回到起点了吗？ | 完成完整房间回路 | 重走被遗漏的一侧 |
| 不确定的区域被标记了吗？ | 待定货架已列出 | 继续前先标记它们 |
| 物品分组记录了吗？ | 电池或其他物品已识别 | 补上类别备注 |
| 房间核验了吗？ | 已做第二轮确认 | 暂时只保留"已整理" |

一份有用的进度记录能立刻回答四个问题：哪些区域已完成、哪些货架待定、本次游戏有多少物品被处理、下一轮路线该从哪里开始。

### 排查数量对不上的问题

如果你的总数与预期不符，不要急着把整个地堡重来一遍。检查记录中的待定条目、重复的货架标签，以及那些标记为已整理却从未核验的房间。这三类通常就藏着误差，而且审计它们远比全面重新搜索快得多。

过早把货架提升为已核验，是玩家最终不得不重走已经清理过的房间的最大原因。已核验的货架应当是一个承诺，而不是一次猜测。

## FAQ：bunker tidy up shelves location

**问：在 Bunker Tidy Up 中我需要整理多少块电池？**
关于该游戏的参考资料与社区内容提到，需要寻找并整理 420 块电池。把这个数字当作坚持基于区域的记录、而非依赖单一累计总数的理由。

**问：追踪每一个 bunker tidy up shelves location 最快的方法是什么？**
给每个货架一个与其房间和位置挂钩的简短标签，然后在你完成检查的那一刻记录状态——未检查、进行中、已整理、已核验或待定。事后补记，正是准确性崩塌的地方。

**问：我应该先搜完整个地堡再开始整理吗？**
不应该。一次只处理一个明确的区域：清扫它、整理它、核验它，然后才继续前进。逐房间推进的方式能让未完成的货架保持可见，而不是把它们埋在一堆散落物品后面。

**问：当货架看起来不完整时我该怎么办？**
把它标为待定而不是完成，等房间路线走完后再回来看。如果有物体或镜头角度挡住了视线，那么在计数之前，这个货架值得再看一眼。

**问：整理完货架后真的还需要核验吗？**
需要。核验是区分"已确认的进度"与"凭希望的进度"的关键。没有它，庞大的收集目标就会变成猜测，而你会重走已经清理过的房间。

一个整洁地堡的核心很简单：一个地标、一个方向、每个货架一个状态。选定一套命名模式，每触碰一个货架就记录它，并在庆祝之前先核验。做到这些，每一个 bunker tidy up shelves location 就不再是疑虑的来源，而会成为一条你可以信赖的清单项。
